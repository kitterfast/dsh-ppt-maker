# 经验教训：HTML → PPTX 转换的完整规则（v2.3 固化）

> 本文档是 2026-09-14/15 多轮真实跑批用血换来的全部结论。**新版本发布前必须通读。**
> 最高指令只有一条：**产出的 PPTX 必须与 HTML 完全一致，且以 WPS 为验收播放器。**

---

## 一、HTML 契约（可转换性的前提，写进生成阶段的提示词）

一份 HTML 要能被 1:1 转换，**必须**满足：

| 要求 | 为什么 | 违反的后果 |
|---|---|---|
| 入场元素用**固定类名** `.a1` … `.aN`，每个类 = 一个图层 | 层数、顺序、延迟只能"读"不能"猜" | 猜错 = 错版 / 动画消失 |
| 全篇**只允许一个** `@keyframes`（命名 `rise`），from/to 明写 `opacity` / `transform` | 效果参数从 keyframes 读：淡入→`animEffect`，位移→`ppt_y` 相对量，旋转→`animRot`（**有 rotate 才写**） | 多 keyframes = 无从映射 |
| 延迟写进 `animation` 简写（如 `rise .5s .04s both`） | 延迟逐个读，逐项写进 `p:cond delay`（**绝对时间**） | 错峰丢失 |
| 触发类固定（`.slide.active` 或 `.slide.on`），并提供可编程翻页入口 | 渲染器要能翻到每一页再截图 | 11 页全拍成第 1 页 |
| **禁止** `animation-iteration-count: infinite` | WPS 时间轴表达不了无限循环 | 常驻动效丢失 |
| **禁止** `<canvas>` 常驻动画（ECharts 静态图除外） | 同 canvas 只有 THREE 动画可烘 GIF（见 §三） | — |

**契约检查**：`tools/extract-anim-spec.mjs <deck.html> --check`（渲染前自动执行，不合格直接拒绝出片）。
**规格提取**：`--json` / `--out=anim-spec.json`，生成器从规格取数，配置里的猜测项只作兜底。

## 二、转换结构（唯一验证过的正确形态）

**基准 = 用户提供的能播稿 `为什么选我做学委_动态版.pptx`**，逐页解剖结果：

```
每页 = 1 张底图（不透明）+ N 张图层（不透明，N = 该页 .aN 数量）
       + 原生时间轴入场（fade + ppt_y 相对量 + animRot，延迟 = HTML 声明）
仅 THREE.js 动画页：额外 1 张循环 GIF（不透明、叠在堆栈上）
```

- **图层必须不透明**：按堆叠顺序把每层合成到底图上再落盘。**WPS 渲染带 alpha 的 PNG/GIF 会出黑块/黑角**（"只黑""缺角"的根因）。
- **ECharts 图表不是 GIF**：图表只是普通图层 + 错峰入场。它的"逐条显现"是页面加载时一次性播完的，成功版根本没有图表 GIF。
- **THREE 画布才烘 GIF**：检测"canvas 且不属于 echarts 实例"。
- 入场 XML 的写法：外层组 par 用 `<p:cond delay="0"/>`；效果 = `presetID=10` + `set style.visibility` + `animEffect in/fade` + 相对 `ppt_y`（末帧**精确** `#ppt_y`）+（HTML 有 rotate 才写 `animRot`）。**照抄"已证实会播"的形式，别自己发明组合**（自检会全绿但放映不动）。
- 时间节点 id 每页从 3 开始；`p:tav@tm` 是**时长的千分比**（0–100000），不是毫秒。

## 三、GIF 烘焙的 8 条规则

1. **按实测帧间隔写每帧延时**：截图本身要 ~90–260ms，`截图 + 固定等待` 会让回放快 2–3 倍（"动画过快"）。
2. **按动画真实周期录满一个循环**：固定录 1.7s 撞 14s 周期 = 每 1.7s 硬跳（"闪烁"）。周期从 `getAnimations()` 的 `duration` 读，可配上限。
3. **不透明**：帧合成到堆栈图上再编码，**不用透明索引**（WPS 黑屏）。
4. **ECharts 重放**：`clear()` + `setOption(getOption())` 可让逐条显现重播，录前调用。
5. **ECharts 5 的 canvas 外包了一层 div**：`getInstanceByDom` 要沿 DOM 向上走 4 层找容器。
6. **`go(n)` 对当前页是空操作**：重录前先跳到别的页再回来。
7. **THREE 需要 GL 上下文**：无头浏览器用 `--use-angle=swiftshader`，**不要 `--disable-gpu`**（会杀死 THREE 渲染）。
8. **无限循环 CSS 用 `getAnimations({subtree:true})`**：动画在子元素（如 `<path>`）上，不带 subtree 永远查不到。

## 四、验收体系（每一道都是教训换来的）

| 闸门 | 工具 | 防什么 |
|---|---|---|
| 契约 | `extract-anim-spec --check` | 输入不可转换 |
| 资源绑定 | 渲染内置 | HTML 引用了不存在的本地文件 / 绝对路径 |
| 结构 | `deck-verify` A | 目标形状、效果数、相对位移 |
| **入场写法** | `deck-verify` A2（与 `lib/reference-entrance.xml` 子集比对） | 自检全绿但放映不动的组合 |
| PowerPoint 真机 | `deck-verify` B（COM） | 效果挂在错误形状 |
| 逐页像素 | `deck-verify` C | 错版、缺角、内容丢失 |
| **WPS 播放** | `tools/wps-show-frames.ps1` | **以 WPS 为准** |

**两条铁律**：
- **能读到 ≠ 会播**。XML 自检只能证明"解析了"；"会不会播"只能放映抓帧证明。
- **WPS 是验收播放器**。COM 驱动的放映不播媒体 —— 曾据此错判"WPS 不播 GIF"。抓帧要：`$app.Visible = -1`（COM 实例默认不可见）+ **从放映开始就抓帧、绝不 `GotoSlide`**（它不重放入场动画）。

## 五、反模式（禁止再犯）

1. **不要用正则猜 XML/形状 id**：第 0 个 `<p:cNvPr>` 是幻灯片自己的组合形状，数组下标整体错位。
2. **不要重新打包 pptx 做 A/B 实验**：任何 re-zip（JSZip/.NET）都会让参考稿动画失效，结论全错。
3. **不要用 `node -e` 在 PowerShell 里打补丁**：引号被吞，替换串会损坏。一律写补丁文件再执行。
4. **`.ps1` 必须纯 ASCII**：PowerShell 按 ANSI 读 .ps1，中文注释会吞掉后面的引号。
5. **PowerShell `>` / `Set-Content -Encoding UTF8` 会写 BOM**：给 Node 读的 JSON 一律用 `--out=` 或 UTF8 no-BOM。
6. **缓存键必须包含一切影响输出的输入**：缺 bits 导致"独立探针找到、生成器里找不到"的假象。
7. **失败分支必须恢复页面状态**：no-motion 分支忘了 `restore()` 会把隔离状态带到下一页，直接崩溃。
8. **渲染截屏用 2× 密度**（`captureScale: 2`）：1× 位图被播放器缩放就发虚（"糊"）。
9. **导航 API 每份稿子不同**：没有全局 `go()` 就点 `#nextBtn/#prevBtn`，用 `#counter` 读当前页。
10. **chrome 选择器要含整条 UI**：漏掉提示条就把它烤进每一页。

## 六、已知边界（诚实告知用户）

- 常驻动效（CSS infinite / canvas rAF）**只能**以 GIF 表达，且是近似（帧率、色深）。
- 文字不可在 PPT 中编辑（栅格化是"完全一致"的唯一途径）；文字进备注页与替换文字。
- 入场缓动是预置+相对关键帧的近似；翻页位移在 PPT 里只有 fade。
